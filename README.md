# אוצר הספרים – שרת (Backend)

שרת למערכת אוצר הספרים של בית הכנסת הגדול, חניכי ישיבת חברון.
מתפללים מחפשים ספרים ושולחים הערות לגבאי. הגבאי מנהל את הספרים ואת ההערות.

- **להעלאה לאינטרנט** – ראי [START-HERE.md](START-HERE.md)
- **לכתיבת צד הריאקט** – ראי [FRONTEND-API-GUIDE.md](FRONTEND-API-GUIDE.md)
- **תיעוד אינטראקטיבי** – `/api-docs` (Swagger), והקובץ [docs/openapi.json](docs/openapi.json)

## טכנולוגיות

Node.js 22 · Express 5 · TypeScript (strict) · PostgreSQL · Prisma · Zod · JWT · bcrypt · Swagger (OpenAPI 3) · Vitest

## מבנה התיקיות

```
src/
  server.ts            הפעלת השרת
  app.ts               הרכבת Express: CORS, אבטחה, Swagger, נתיבים, שגיאות
  config/env.ts        קריאה ובדיקה של משתני הסביבה
  db/prisma.ts         חיבור למסד הנתונים
  routes/index.ts      כל הנתיבים, ומי רשאי לגשת לכל אחד
  controllers/         מקבלים בקשה, בודקים קלט, מחזירים תשובה
  services/            הלוגיקה: חיפוש, איחוד ספרים כפולים, הרשאות מיוחדות
  schemas/             כללי תקינות (Zod) לכל קלט
  middleware/          אימות (JWT), הרשאות לפי תפקיד, טיפול בשגיאות
  lib/                 עזרים: JWT, שגיאות, נרמול טקסט עברי
  docs/openapi.ts      תיעוד Swagger
prisma/
  schema.prisma        מבנה הטבלאות
  migrations/          היסטוריית השינויים במבנה
  seed.ts              נתוני הדגמה
  import-catalog.ts    טעינת הקטלוג המודפס
  data/catalog.json    הקטלוג (אלול תשפ"ו), כ־2,200 שורות
tests/                 בדיקות אוטומטיות
docs/openapi.json      תיעוד ה־API כקובץ
```

## הרצה במחשב

צריך: Node.js 22 ומסד נתונים PostgreSQL. הכי פשוט: מסד נתונים חינמי ב־Neon (ראי START-HERE.md, חלק ב). אפשר לפתוח שני מסדי נתונים, אחד רגיל ואחד לבדיקות.

```bash
npm install                 # מתקין ספריות ויוצר את Prisma Client
cp .env.example .env        # ואז למלא DATABASE_URL, TEST_DATABASE_URL, JWT_SECRET
npm run db:deploy           # יוצר את הטבלאות
npm run db:seed             # משתמשים וספרים לדוגמה
npm run import:catalog      # (לא חובה) טעינת כל הקטלוג
npm run dev                 # השרת עולה על http://localhost:3000
```

משתמשי הדגמה (בסביבת פיתוח בלבד):

| תפקיד | שם משתמש | סיסמה |
| --- | --- | --- |
| גבאי | `gabbai` | `gabbai1234` |
| מתפלל | `mitpalel` | `mitpalel1234` |

## מה נבדק ומה עוד צריך לבדוק

הפרויקט נבנה בסביבה שבה **אי אפשר היה להוריד ספריות מ־npm**. לכן חלק מהבדיקות עוד לא הורצו.

**נבדק בפועל:**
- ה־migration הורץ על PostgreSQL 16 אמיתי, ויצר את 3 הטבלאות. נבדקו האילוצים: שם משתמש ייחודי, ספר כפול נחסם, מחיקת ספר משאירה את ההערה עם שם הספר, ומחיקת משתמש מוחקת את ההערות שלו.
- הקטלוג נטען למסד הנתונים עם אותה לוגיקה של `import-catalog.ts`: 2,216 שורות, שהם 2,151 ספרים שונים (2,216 עותקים). כל השדות נכנסים באורך המותר.
- 12 בדיקות של נרמול הטקסט העברי (חיפוש בלי גרשיים, זיהוי כפילויות, מספרי מדף) עברו.
- `docs/openapi.json` נוצר, וכל 17 הנתיבים שבשרת מתועדים בו.
- בדיקת תחביר TypeScript לכל הקבצים.

**עוד לא הורץ:** `npm install`, בדיקת הטיפוסים המלאה, ה־build והבדיקות האוטומטיות שבתיקייה `tests/`.
כדי להריץ אותם במחשב עם אינטרנט רגיל:
```bash
npm install
npm run check
```
(צריך `.env` עם `DATABASE_URL`, `TEST_DATABASE_URL` ו־`JWT_SECRET`.) אם משהו נכשל, שלחי לי את הפלט.

## החלטות חשובות במערכת

- **חיפוש סלחני:** לכל ספר נשמר שדה `searchText`, עם השם, הנושא, המחבר והמדף בצורה מנורמלת (בלי גרשיים, ניקוד, אותיות סופיות ומקפים). החיפוש מנרמל גם את מה שהמשתמש הקליד, ובודק שכל מילה מופיעה.
- **ספר כפול:** `dedupeKey` = שם + מחבר + מדף מנורמלים, ונשמר כ־Unique. הוספה של ספר קיים מעלה את הכמות במקום ליצור שורה חדשה.
- **ספרים חדשים:** `addedAt` נקבע רק כשגבאי מוסיף ספר. ספרים שיובאו מהקטלוג נשארים עם `addedAt = null`, כדי שלא יוצגו כחדשים.
- **הרשאות:** התפקיד נקרא ממסד הנתונים בכל בקשה, ולא מהטוקן. כך גבאי שהורד מתפקידו מאבד את ההרשאות מיד.
- **אבטחה:** סיסמאות מוצפנות ב־bcrypt, הטוקן תקף שעתיים, יש הגבלת ניסיונות כניסה, ושדה `userId` שהלקוח שולח לא משפיע: השולח נקבע לפי הטוקן.
